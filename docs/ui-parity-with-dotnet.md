# UI 与 .NET 版一致性对照

**目的：** 记录 Python 版（PySide6）与 .NET 版（WPF）界面的逐页对照结果。
**基准：** `src/JingXu.Workbench/Features/*/View.xaml` 的区块标题、控件文案与顺序。

> **关于「一模一样」的边界**：两版渲染栈不同（WPF vs Qt），控件外观、字体度量、
> 圆角与动画无法逐像素相同。本对照追求的是**结构一致、文案一致、分区一致、
> 交互一致**——即用户看到同样的区块、同样的措辞、按同样的顺序操作。
> 若要求像素级一致，需要放弃 Qt 改用与 .NET 同源的方案，不在本次范围内。

## 已对齐

| 页面 | 状态 | 说明 |
|------|------|------|
| 混剪 | ✅ | 区块顺序与 .NET 完全一致：输出目录 → 文件名前缀 → 输出质量 → 处理器 → 导出兼容性（输出分辨率/输出帧率）→ 统一比例；分辨率与帧率文案已对齐（`1080P` / `720P`、`原帧率（跟随首段）`） |
| 蒙版 | ✅ | 「蒙版素材库 + 蒙版轨道」两段式；「合成预览」；「叠加参数」含宽度/高度/源素材适配/透明度/分割位置/上向渐变/羽化；**新增「源素材取景（独立于输出叠层框）」四个数值 + 重置为自动** |
| 贴纸 | ✅ | 「贴纸素材库 + 贴纸轨道」两段式，轨道由素材库「添加」生成；参数只保留贴纸画法（X/Y/宽/高/透明度/旋转/固定比例）；预览下方参数摘要；「随机贴纸库」开关 |

| 队列 | ✅ | 计数（共 N 个 · 渲染中 · 排队 · 已结束 · 失败）与「队列为空」空态一致 |
| 设置 | ✅ | 应用/版本/数据目录/渲染并发/缓存与临时文件/GPU 加速/运行时诊断分区一致 |
| 下载 | ✅ | 保存目录、链接输入、任务/文件名/状态/进度/速度/说明表头一致 |
| 音频 | ✅ | 音频库 + 最近使用；空态提示一致 |

## 未对齐（已知差异）

| 页面 | 差异 | 影响 |
|------|------|------|
| 字幕 | .NET 用「**预览与区域选择**」（导入视频后在画面上**框选**字幕区域）+「检测与识别」+「去字幕方式」；Python 版只有「烧录样式」「硬字幕去除」「OCR 自动定位」，区域靠**手填百分比** | **功能性差异**：无法在画面上框选区域，用户反馈「字幕功能不用」的主因 |
| 蒙版 | .NET 的「蒙版区域预览」同时画出暗红默认叠区、蓝色输出框与白色源取景框，可**拖拽三者**调整；Python 版只有图层预览画布（可拖位置/滚轮改宽度） | 交互差异：不能直接拖输出框与取景框 |
| 贴纸 | .NET 「成片画面示意」是独立示意画布并标注位置/尺寸百分比；Python 版改为画布 + 一行参数摘要 | 信息等价、位置不同 |
| 选品 | .NET 有「最近报表」「打开独立界面」入口；Python 版有「打开报表目录」 | 入口形态不同，功能等价 |
| 音频 | .NET 音频库为独立浮层；Python 版内嵌在音频页 | 位置不同 |

## 下一步建议顺序

1. **字幕页框选区域**（功能性差异，影响最大）
2. 蒙版页预览中拖拽输出框与取景框
3. 其余为形态差异，可按需处理

## 本轮为对齐所做的修复

除文案与分区外，对齐过程中发现并修掉了几个真实缺陷：

| 缺陷 | 后果 |
|------|------|
| `Qt.Edge` 直接 `int()`（PySide6 6.x Flag 枚举） | 每次窗口左键按下抛异常、边缘拖拽缩放失效、崩溃日志被刷满 |
| 贴纸页与蒙版页共用同一参数表单 | 贴纸页显示羽化/蒙版适配/源上下偏移等蒙版专属项，无法理解 |
| 贴纸页没有素材库 | 只能靠「导入素材」逐条建轨道，缺少「库 → 轨道」流程 |
| 选品页单条添加默认强制「抖音」 | 粘贴快手链接被存成抖音账号（绕过自动识别） |
| 账号表窄窗口下挤掉列 | 「平台」列消失，账号串到链接列，看着像平台识别错 |
| 源素材取景只有后端没有入口 | 用户无法设置手工取景 |
