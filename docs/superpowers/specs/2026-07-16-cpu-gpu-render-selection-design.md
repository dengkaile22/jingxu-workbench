# CPU / GPU 渲染处理器选择设计

> **存档（2026-09-23）：** 本文以 .NET/WPF 时期的路径与类型为证据，该参照树已移除（git 标签 `last-dotnet-reference`）。现行技术栈为 Python（`src/JingXu.Workbench.Py`），文中 `.cs`/`.xaml` 路径仅作历史记录。

## 目标

在混剪页“输出质量”附近增加每次入队生效的处理器选择：

- `自动（推荐）`
- `CPU（兼容稳定）`
- `GPU（硬件加速）`

选择结果必须写入每个 `RenderRequest` 快照。任务入队后，即使用户更改页面选项，也不得影响已排队任务。

GPU 模式自动识别并尝试：

1. NVIDIA NVENC
2. Intel Quick Sync Video（QSV）
3. AMD AMF

GPU 不可用或发生明确的硬件编码初始化故障时，任务自动改用 CPU 编码并继续渲染，同时在队列任务和日志中保留回退提示。

## 非目标

- 不启用 `-hwaccel auto`，不强制硬件解码。
- 不把缩放、裁切、蒙版、羽化、贴纸等软件滤镜迁移到 GPU。
- 不增加 HEVC/H.265、AV1 或显卡厂商的手动下拉选择。
- 不承诺所有工程都获得明显提速；复杂蒙版和贴纸仍主要消耗 CPU。

## 方案比较

### 方案 A：只根据选择切换编码器

直接把 `libx264` 换成 `h264_nvenc`、`h264_qsv` 或 `h264_amf`。

优点是改动少。缺点是 FFmpeg 编译进编码器并不代表机器上存在对应显卡或驱动，正式渲染可能启动后才失败，用户体验不可靠。

### 方案 B：运行探测、缓存能力、失败回退（采用）

执行器使用当前解析到的 FFmpeg 做一次短时、低分辨率编码探测，确认编码器和驱动都能工作。探测结果按 FFmpeg 路径在进程内缓存。正式任务选择可用编码器；出现明确硬件初始化错误时只重试一次 CPU。

该方案兼顾可靠性、可测试性与启动成本。

### 方案 C：全硬件滤镜管线

同时启用硬件解码、硬件帧上传以及 GPU 缩放/合成。

理论性能上限更高，但 NVENC/QSV/AMF 的滤镜能力不同，现有 `scale/crop/geq/gblur/overlay/alphamerge` 链无法直接通用，容易重新引入驱动和帧格式兼容问题，因此不在本次范围内。

## 用户界面

在混剪页“输出质量”区域下方增加“处理器”分段选择器：

- 自动（推荐）：优先使用可用 GPU；没有可用 GPU 时直接使用 CPU。
- CPU：固定 `libx264`。
- GPU：优先使用可用 GPU；不可用时自动回退 CPU，并显示提示。

默认值为“自动（推荐）”。

质量提示区域追加以下说明：

- 无损直拷且未触发转码时，处理器选择不参与执行。
- 进入转码时，显示当前选择策略。
- GPU 只加速最终编码；复杂蒙版、羽化、贴纸仍由 CPU 计算，所以提速幅度依工程而异。

加入队列后的状态提示应包含 `自动处理器`、`CPU` 或 `GPU`。

## 领域模型与任务快照

新增领域枚举 `VideoProcessingMode`：

- `Auto`
- `Cpu`
- `Gpu`

在 `RenderRequest` 末尾增加带默认值的 `ProcessingMode` 字段，避免破坏现有调用方。`RenderProfile` 继续只表达画质、音频码率与 CPU preset；删除现有未实际生效的 `PreferHardwareEncoder` 字段，避免出现两个互相冲突的编码器选择来源。

`RenderRequestFactory` 接收处理器模式，并把它复制到每条批量请求。

## 编码器选择

基础设施层新增纯数据类型：

- `VideoEncoderKind`: `Libx264`、`H264Nvenc`、`H264Qsv`、`H264Amf`
- `VideoEncoderSelection`: 编码器类型、显示名称、是否发生回退、提示文本
- `IVideoEncoderSelector`: 通过异步 `SelectAsync` 根据 FFmpeg 路径与处理器模式返回选择结果

选择优先级固定为 NVENC → QSV → AMF。固定顺序便于测试和复现；在同时拥有核显和独显的机器上优先使用 NVIDIA 独显。

### 可用性探测

每个候选编码器执行一个短时、64×64、无音频的 H.264 空输出测试。探测需：

- 使用当前任务实际解析到的 FFmpeg。
- 设置较短超时。
- 不创建持久输出文件。
- 捕获退出码和精简错误。
- 按规范化 FFmpeg 绝对路径缓存结果，同一应用会话不重复探测。

“自动”在没有可用 GPU 时正常选择 CPU，不产生警告；“GPU”在没有可用 GPU 时选择 CPU，并产生“GPU 不可用，已改用 CPU”的提示。

## FFmpeg 命令编译

`FfmpegCommandCompiler` 保持纯函数，不自行启动探测进程。执行器先取得 `VideoEncoderSelection`，再把明确的编码器类型传给编译器。

所有编码器继续输出 H.264、`yuv420p` 和 AAC，保持现有播放兼容性。

质量映射由一个集中方法维护：

- CPU：`libx264` + 现有 `-preset` + `-crf`
- NVENC：`h264_nvenc -tune hq -rc vbr -b:v 0 -cq <质量值>`；preset 为高质量 `p6`、平衡 `p5`、小体积 `p4`、快速 `p2`
- QSV：`h264_qsv -global_quality <质量值>`；preset 为高质量 `slow`、平衡 `medium`、小体积 `faster`、快速 `veryfast`
- AMF：`h264_amf -rc cqp -qp_i <质量值> -qp_p <质量值> -qp_b <质量值>`；quality 为高质量 `quality`、平衡 `balanced`、小体积/快速 `speed`

`<质量值>` 沿用现有档位：高质量 18、平衡 22、小体积 27、快速 26。用户选择“无损直拷”但因滤镜等原因必须转码时，沿用当前行为降级为平衡质量值 22。

具体参数必须由编译器测试固定，禁止在多个位置分别拼接。

滤镜图仍输出软件帧给硬件编码器，不添加 `-hwaccel auto`。

## 执行与回退

执行流程：

1. 正常预检并解析 FFmpeg。
2. 根据任务快照选择编码器。
3. 编译并执行第一次渲染。
4. CPU 失败时沿用现有失败处理。
5. GPU 失败时检查错误是否属于硬件编码器初始化、设备丢失、驱动不可用或会话不足。
6. 只有命中硬件错误时，删除未完成的临时输出，重新以 `libx264` 编译并执行一次。
7. CPU 重试成功后任务完成，并保存回退提示；CPU 重试失败则返回第二次失败，同时在日志中保留 GPU 首次失败信息。

普通滤镜错误、输入错误、磁盘错误不得伪装成 GPU 故障，也不得无条件重复整条渲染。

日志按以下结构保存：

- 选择的处理器和编码器
- GPU 探测摘要
- 第一次执行输出
- 回退原因（如有）
- CPU 重试输出（如有）

## 队列提示

为完成任务保留非错误提示，在 `RenderExecutionResult` 与 `RenderJob` 增加可选 `Notice`：

- 正常 GPU：`使用 NVIDIA GPU（NVENC）完成`
- 自动选择 CPU：`使用 CPU 完成（自动选择）`
- GPU 回退：`GPU 编码不可用，已自动改用 CPU 完成`

自动模式没有可用 GPU 时属于正常选择，不显示警告色；队列完成行可显示处理器信息。GPU 模式发生回退时显示明确提示；失败仍使用现有 `Error`。

## 错误处理

- 探测超时或探测程序异常：将该 GPU 编码器视为不可用，不阻塞队列。
- 所有 GPU 均不可用：自动模式静默选 CPU；GPU 模式带提示选 CPU。
- GPU 正式编码硬件初始化失败：最多回退一次 CPU。
- CPU 重试失败：任务失败，不进行第三次尝试。
- 用户取消：立即取消，不得触发 CPU 回退。
- 无损直拷：不探测 GPU，不改变 stream-copy 命令。

## 测试

采用测试驱动开发，至少覆盖：

### 领域与应用层

- 默认处理器为 `Auto`。
- 混剪页选择 CPU/GPU/自动后，批量请求均保存对应快照。
- 已入队任务不受页面后续修改影响。
- 无损直拷请求仍保留选择，但不会触发编码器探测。

### 编码器选择器

- NVENC、QSV、AMF 优先级正确。
- 单一可用编码器能被选择。
- 自动模式无 GPU 时选 CPU且不警告。
- GPU 模式无 GPU 时选 CPU并返回提示。
- 探测结果按 FFmpeg 路径缓存。
- 探测取消和超时行为正确。

### 命令编译

- CPU 使用 `libx264/-preset/-crf`。
- NVENC、QSV、AMF 分别生成正确且唯一的编码参数。
- GPU 命令不包含 `-hwaccel auto`。
- 所有路径继续使用参数列表，不拼接 shell 命令。

### 执行器

- GPU 硬件初始化失败后仅重试一次 CPU并成功。
- 非硬件滤镜错误不触发回退。
- 用户取消不触发回退。
- 日志包含两个尝试和回退原因。
- 回退成功时队列完成并显示 Notice。

### 界面与集成

- 三个处理器按钮可见、互斥、默认自动。
- 质量提示准确说明无损直拷和 GPU 限制。
- 使用实际 FFmpeg 时，CPU 集成渲染通过。
- 如果测试机存在可用硬件编码器，额外运行 GPU 短渲染；否则明确跳过。
- 完整测试、发布构建、发布版烟测通过后，直接镜像覆盖 `dist`。

## 验收标准

- 用户可以在混剪页明确选择自动、CPU 或 GPU。
- GPU 自动识别 NVENC/QSV/AMF。
- GPU 不可用不会导致任务直接报废，而是自动使用 CPU。
- 回退原因可在队列或日志中看到。
- 复杂蒙版、贴纸、随机替换和现有输出质量功能不回归。
- 新版本最终位于工作区 `dist`，并通过文件清单、哈希和发布版烟测。
