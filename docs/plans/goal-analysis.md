## Organized Goals

1. Triage and stabilize the current JingXu.Workbench implementation by quantifying test failures per project, identifying root causes, and prioritizing the highest-impact fixes that will restore a runnable baseline.
2. Complete the unfinished feature implementation work across domain/application/infrastructure/presentation layers to match the implementation plan, focusing first on functionality that unblocks later milestones and on closing open gaps in committed and uncommitted work.
3. Fix broken automated tests and align test behavior with production-readiness requirements, especially async WPF/ViewModel execution, FFmpeg/FFprobe/Whisper/Tesseract abstractions, overlay/subtitle workflows, and queue/render coordination.
4. Ensure the full solution builds cleanly, tests pass at least to the required milestone gate, and the project remains consistent with the existing clean-architecture boundaries, coding conventions, and offline-first constraints.
5. Prepare the repository for committing/packaging the completed work so the project can move toward release readiness, including documentation and verification hooks already present in the plan.

## Dependencies Between Goals

- Goal 2 depends on Goal 1: implementation prioritization requires knowing which layers and tests are currently broken.
- Goal 3 depends on Goal 2: many tests will only become stable once the surrounding implementations are aligned and production-shaped.
- Goal 4 depends on Goals 2 and 3: build/test green state requires both correct implementations and reliable tests.
- Goal 5 depends on Goal 4: packaging/commit readiness follows after stabilization.

## Inferred Requirements

- [INFERRED] Preserve the existing architecture split (Domain, Application, Infrastructure, Presentation) while completing the remaining work; do not collapse layers or bypass abstractions to force green tests.
- [INFERRED] Focus on production-readiness over quick fixes: deterministic async behavior, cancellation-safe UI integration, error handling, and observable state must be treated as first-class deliverables.
- [INFERRED] Keep changes constrained to the worktree `.worktrees/jingxu-implementation/` and respect the existing plan document as the execution reference.
- [INFERRED] Maintain compatibility with .NET 10 / WPF / xUnit / System.Text.Json stack already used in the repo.

## Constraints & Boundaries

- Work must remain offline-capable; no new cloud/online dependencies.
- No speculative refactors beyond what is necessary to complete and stabilize the plan.
- Keep domain purity: Domain must not reference WPF, filesystem, or process concerns.
- External processes must continue to use argument lists, not shell command strings.
- Tests must remain production-asserting, not implementation-detail-only.
- Time/effort is not a deciding factor; robustness, maintainability, and convention consistency are.

## Open Questions

- Which test failures are caused by implementation gaps versus incorrect/fragile test harness behavior?
- Are there uncommitted code changes that already attempt task completion but need correction, alignment, and integration?
- Which remaining tasks are closest to completion and can be finished first to unlock broader stability?
