# 镜序工作台设计规格

**日期：** 2026-07-10

**状态：** 已完成口头设计确认，待书面规格复核

**目标平台：** Windows 10/11 64 位

**工作名称：** 镜序工作台（`JingXu.Workbench`）

## 1. 项目目标

开发一款完全离线的 Windows 桌面视频批处理软件。软件把按文件名编号的视频素材完整拼接为多条成片，支持随机顺序和自定义序号顺序，并提供画幅、滤镜、贴纸、BGM、多层视频蒙版、差异化处理、硬字幕去除、离线语音识别、字幕替换、封面生成、批量队列和可恢复渲染。

产品面向需要反复处理大量短视频素材的中文用户。界面必须像专业制作工具：信息密度适中、操作路径短、错误信息清楚，不使用紫色渐变、发光卡片、夸张插画或模板化“AI 助手”文案。

## 2. 范围拆分

产品在同一个安装包和主窗口内交付，工程上拆成三个可独立测试的业务子系统：

1. **批量混剪与差异化处理**：素材探测、序号解析、随机/自定义编排、质量策略、滤镜、贴纸、BGM、封面和批量输出。
2. **蒙版与模板系统**：三类视频蒙版、多层合成、素材库、随机抽取、循环补齐和参数模板。
3. **离线字幕实验室**：手动/自动硬字幕定位、裁切/模糊/修补、SRT/ASS 导入、本地语音识别、字幕编辑和烧录。

三个子系统共享项目存储、媒体探测、FFmpeg 进程执行、任务队列、日志和设置模块。

## 3. 非目标

- 不上传用户视频、音频、字幕或项目数据。
- 不提供云端账号、云同步、协作或在线素材商城。
- 不承诺任何差异化处理一定通过第三方平台的重复内容判定。
- 不做重复文件扫描和自动删除；“批量去重”指生成可配置的差异化成片。
- 不做非线性剪辑时间线、逐帧动画或专业调色软件的完整替代品。
- 首版只支持 Windows x64，不支持 macOS、Linux 或 ARM64。

## 4. 技术选型

### 4.1 应用技术栈

- **运行时：** .NET 10 LTS、C#、`net10.0-windows`。
- **桌面 UI：** WPF，MVVM；只使用定制 XAML 样式和模板，不依赖默认控件外观。
- **视频引擎：** 独立的 `ffmpeg.exe` 与 `ffprobe.exe` 子进程。
- **本地语音识别：** `whisper.cpp` 命令行运行时，默认随包提供多语言 base 模型；允许用户切换兼容的大模型。
- **本地硬字幕 OCR：** Tesseract OCR 命令行运行时，随包提供简体中文和英文语言数据。
- **持久化：** `System.Text.Json`；项目、队列和设置分别保存为版本化 JSON，采用临时文件写入后原子替换。
- **日志：** 内存可观察日志 + 每任务 UTF-8 文本日志；发布包保留最近 30 天，用户可手动清理。
- **测试：** xUnit；纯领域逻辑使用单元测试，媒体管线使用自动生成的短视频做集成测试。
- **安装与分发：** `dotnet publish` 生成 self-contained `win-x64` 便携版；WiX Toolset 生成安装程序。

### 4.2 选择 WPF 的理由

WPF 与 Windows 的文件系统、进程树、任务栏、拖放、对话框和安装链集成直接。FFmpeg 渲染是长时间后台进程，C# `Process` 的异步输出读取、取消和进程树终止比 WebView IPC 路线更简单。离线模型与 FFmpeg 决定了最终包体，Tauri 的小外壳优势有限；Electron 还会额外打包 Chromium 和 Node。

### 4.3 FFmpeg 分发规则

应用通过普通命令行参数和管道调用独立 FFmpeg，不链接 `libav*`。运行时解析顺序为：

1. 应用目录 `runtime/ffmpeg/`；
2. 用户在设置中指定的目录；
3. 系统 `PATH`。

完整发布包必须包含第三方许可证、FFmpeg 构建配置和对应源码获取方式。开发机现有 FFmpeg 为 GPLv3 full build，可用于本地开发和验收；对外分发前必须按最终商业策略复核 FFmpeg、编码器和专利许可。应用不得捆绑带 `--enable-nonfree` 的 FFmpeg 产物。

## 5. 核心业务规则

### 5.1 素材导入与序号识别

- 支持拖放或选择多个文件、一个文件夹以及多个文件夹。
- 支持 MP4、MOV、MKV、AVI、WEBM 和 M4V；实际解码能力以当前 FFmpeg 运行时为准。
- 导入后用 FFprobe 读取时长、画面尺寸、显示宽高比、帧率、视频/音频编码、旋转信息和音频轨道状态。
- 默认取文件名最后一个连续数字片段作为序号，例如 `商品_片段_12.mp4` 的序号为 `12`。
- 未识别到序号时使用导入顺序并显示警告；重复序号必须由用户选择保留、重新编号或移除后才能执行自定义序号拼接。
- 素材列表显示缩略图、文件名、序号、时长、分辨率、帧率和错误状态，并支持拖动排序。

### 5.2 随机拼接

- 一条成片默认完整使用当前任务内的每个素材一次，不裁剪、不变速。
- 使用可保存的随机种子生成排列；相同项目、素材集合和随机种子必须得到相同顺序。
- 批量生成多条成片时，在排列空间允许的范围内避免重复顺序；排列耗尽时给出提示后才允许重复。
- 六段各 30 秒且无转场时，成片目标时长为 180 秒，允许的容器时间戳误差为一帧或 100 毫秒中的较大者。

### 5.3 自定义序号拼接

- 单位数字序号支持紧凑输入，例如 `264513`。
- 任意位数序号使用逗号输入，例如 `2,6,14,5,1,3`。
- 允许用户有意重复或省略序号；界面在生成前展示展开后的真实素材顺序和预计时长。
- 输入不存在、歧义或被禁用的序号时禁止入队，并在具体位置显示错误。

### 5.4 时长与转场

- 默认使用硬切，确保成片时长等于所选素材时长之和。
- 所有差异化处理都不得改变素材播放速度或业务定义的素材时长。
- 可选交叉转场会产生片段重叠。启用时界面必须实时显示转场后的实际时长，不再承诺简单相加时长。

### 5.5 画幅与适配

- 输出画幅可选择继承第一条素材或自定义常用比例与分辨率。
- 内置 9:16、16:9、1:1、4:5 和自定义宽高。
- 异比例素材可选择智能居中裁切、模糊背景填充或黑边填充；默认不拉伸画面。
- 旋转元数据在探测阶段标准化，预览和成片方向必须一致。

### 5.6 差异化处理、滤镜、贴纸与 BGM

- “批量去重”提供可组合的镜像、1%–3% 安全裁切/缩放、轻量调色、轻量降噪、画面占比调整和输出元数据清理。
- 所有随机参数都由任务随机种子派生，结果可复现。
- 滤镜、标题文字、图片贴纸、GIF/视频贴纸和 BGM 参数可保存为命名模板。
- 未选择 BGM 时保留原声；选择 BGM 后默认循环到成片结束，原声 100%、BGM 18%，两者音量可调，BGM 尾部默认淡出 1 秒。
- 贴纸支持位置、尺寸、透明度、开始/结束时点和层级；模板保存相对坐标，适配不同分辨率。

### 5.7 视频蒙版

“添加蒙版”按钮提供三种模式，三种模式均可多层叠加：

1. **自由覆盖层**：可调位置、尺寸和透明度；默认预设为截图所示的顶部全宽矩形区域。
2. **全屏低透明度覆盖**：蒙版缩放裁切到整个输出画面，默认透明度 20%。
3. **形状遮罩**：支持矩形、圆角矩形、椭圆和用户导入的灰度/透明 PNG 遮罩。

共同规则：

- 可指定从第 N 个主素材开头开始；系统根据前面素材的累计时长换算为绝对时间点。
- 默认丢弃蒙版音频，可显式选择混入。
- 蒙版素材时长不足时持续循环，并裁切到与成片最后一个时间戳对齐。
- 蒙版素材库记录文件引用、标签、缩略图和最近使用时间；随机抽取使用任务种子，结果可复现。
- 支持填满裁切、完整适配和拉伸三种适配方式；默认填满裁切。

### 5.8 去字幕与换字幕

字幕实验室提供两条可在软件内选择的工作流。

**手动工作流：**

- 在预览画面框选字幕区域。
- 去除方式包括裁切后重构画幅、区域模糊和 FFmpeg `delogo` 邻域修补。
- 可导入 SRT/ASS、手动新建字幕或粘贴带时间码文本。

**自动离线工作流：**

1. FFmpeg 默认每 0.5 秒抽取一帧，单个视频最多抽取 3600 帧；超过上限时等距采样。默认扫描画面下方 45%，用户可切换全画面。
2. Tesseract 输出文字框、置信度和文本；应用跨帧聚类得到稳定字幕区域与出现时间段。
3. 用户在预览中确认或调整区域，选择修补、模糊或裁切。
4. `whisper.cpp` 从本地音轨识别中文、英文及混合语音，生成带时间码的字幕草稿。
5. 用户在字幕表格中编辑文字、起止时间、样式和位置，再烧录到成片。

自动检测结果必须允许人工修正；低置信度片段不得静默删除。所有帧、音频和模型推理均在本机完成。

### 5.9 输出质量

- **无损直拷：** 仅在未启用画幅变化、滤镜、贴纸、蒙版、字幕或音频混合，并且所有输入的编码、时基和流结构兼容时可用。
- **高质量：** 保持目标分辨率与帧率，软件编码默认 CRF 18、AAC 192 kbps。
- **平衡：** 默认 CRF 22、AAC 160 kbps。
- **小体积：** 默认 CRF 27、AAC 128 kbps。
- 支持在可用时选择 NVENC、QSV 或 AMF；不支持时自动回退到软件编码并明确提示。
- 存在任何视频滤镜或覆盖层时必须重新编码，界面显示“需重新编码”，不得仍标记为无损。

### 5.10 封面与输出目录

- 封面可选择第一条素材的首帧或最终成片最后一帧。
- 输出 JPEG 封面文件；容器支持时可同时写入封面元数据。
- 单一源文件夹任务默认输出到源目录下的 `分镜输出`。
- 多来源任务默认输出到项目目录下的 `分镜输出`。
- 用户可为项目或单个任务指定自定义目录。
- 同名文件不静默覆盖，自动追加三位序号；用户可显式选择覆盖策略。

## 6. 界面设计

### 6.1 总体布局

采用已确认的“制作工作台”布局：

- **顶部标题栏**：项目名、保存状态、离线状态、最小化/最大化/关闭。
- **左侧模块导航**：批量混剪、蒙版模板、字幕处理、任务队列、设置。
- **素材栏**：素材/文件夹分组、序号、缩略图和媒体信息。
- **中央编排区**：随机/自定义模式切换、实际拼接顺序、预计时长和画面预览。
- **右侧参数栏**：当前模块的画幅、质量、效果、蒙版、字幕、封面和导出参数。
- **底部队列**：任务状态、进度、剩余时间、当前阶段、日志、取消、重试和打开目录。

队列暂停只停止调度新任务，已经运行的 FFmpeg 任务继续完成；取消单个任务会终止其完整进程树并清理未完成的临时输出。

### 6.2 视觉语言

- 背景为低饱和暖灰，主色为深墨绿，警告/运行状态使用克制的琥珀色，失败使用暗红色。
- 采用 4/8 像素间距体系、1 像素边框、4–8 像素圆角和轻量阴影。
- 正文使用可随包分发的开源中文字体，数字和时间码使用等宽字体。
- 主要按钮只在当前流程唯一主操作上使用实心色；其余为描边或文本按钮。
- 所有图标必须有文字提示；不得仅用颜色表达状态。
- 动效限于 120–180 毫秒的状态过渡，不使用持续漂浮、渐变流动或装饰粒子。

## 7. 架构与模块边界

```text
JingXu.Workbench (WPF)
  ├─ Presentation
  │   ├─ Shell / Navigation
  │   ├─ Materials / Composition / Overlays
  │   ├─ SubtitleLab
  │   └─ RenderQueue / Settings
  ├─ Application
  │   ├─ ProjectService
  │   ├─ CompositionPlanner
  │   ├─ TemplateService
  │   ├─ SubtitleWorkflow
  │   └─ RenderCoordinator
  ├─ Domain
  │   ├─ MediaAsset / SequenceToken
  │   ├─ CompositionPlan / OverlayLayer
  │   ├─ SubtitleCue / RenderProfile
  │   └─ RenderJob / JobState
  └─ Infrastructure
      ├─ FfprobeMediaProbe
      ├─ FfmpegCommandCompiler / ProcessRunner
      ├─ WhisperRunner / TesseractRunner
      ├─ JsonProjectStore / JsonQueueStore
      └─ RuntimeResolver / FileSystem / JobObject
```

关键边界：

- Domain 不引用 WPF、文件系统、FFmpeg 或模型运行时。
- 命令生成器只接受强类型计划对象并返回参数列表，不接受任意 shell 字符串。
- ProcessRunner 负责并行读取 stdout/stderr、进度解析、取消和 Windows Job Object；业务层不直接创建进程。
- WPF ViewModel 只编排用例和可观察状态，不拼接 FFmpeg 参数。
- 每个主要文件保持单一职责，原则上不超过 800 行，超过前必须拆分。

## 8. 关键数据模型

- `ProjectDocument`：版本、项目名、素材集合、模板引用、导出设置和最近任务。
- `MediaAsset`：稳定 ID、路径、序号、媒体探测结果、缩略图和可用状态。
- `CompositionRequest`：随机/自定义模式、成片数量、种子、序号表达式和效果模板。
- `CompositionPlan`：已展开的素材顺序、累计时间轴、预计时长和所需转码原因。
- `OverlayLayer`：模式、素材来源、起始素材索引、时间范围、相对矩形、透明度、适配、音频和层级。
- `SubtitleProject`：检测区域、识别结果、字幕条目、样式和去除方式。
- `RenderProfile`：画幅、分辨率、帧率策略、编码器、质量档和音频参数。
- `RenderJob`：不可变请求快照、状态、进度、输出、日志、尝试次数和错误信息。

JSON 文档带显式 `schemaVersion`。读取未知新版本时只读打开并提示升级，不丢弃数据。

## 9. 任务状态与数据流

状态机：

```text
Draft → Queued → Preparing → Running → Finalizing → Completed
                    │          │           │
                    └──────────┴───────────┼→ Failed → Queued (重试)
                                          └→ Cancelled
```

数据流：

1. 导入素材并执行 FFprobe 探测。
2. CompositionPlanner 解析随机或自定义顺序，计算累计时间轴。
3. 用户配置画幅、效果、蒙版、字幕、质量和输出。
4. 入队时生成不可变的 `RenderJob` 快照，后续界面修改不影响已入队任务。
5. RenderCoordinator 根据有界并发调度任务。
6. FfmpegCommandCompiler 生成参数列表；ProcessRunner 在 Windows Job Object 中启动运行时。
7. 解析 `-progress pipe:1` 更新进度；stderr 持续写入日志，两个流始终异步排空以避免死锁。
8. 输出先写入任务临时目录；探测验证成功后原子移动到目标位置并生成封面。
9. 每次状态变化都原子保存队列，应用重启后将中断的 Running 任务标为可重试。

## 10. 并发、取消与资源管理

- 默认同时执行 1 个编码任务，用户可选择 1–4；界面提示高并发可能降低总吞吐量。
- 媒体探测允许最多 4 个轻量并发；OCR/ASR 默认各 1 个并发。
- “暂停队列”只阻止新任务启动，不强制暂停正在编码的媒体进程。
- “取消任务”通过 Windows Job Object 终止 FFmpeg/Whisper/Tesseract 及其后代进程。
- 临时目录位于输出目录同卷，确保最终移动可原子完成；失败和取消后清理临时媒体，保留文本日志。

## 11. 错误处理

入队前执行预检：

- FFmpeg/FFprobe 与所需本地模型是否可用；
- 输入文件是否存在且可读；
- 序号表达式是否可解析；
- 编码器和滤镜是否被当前 FFmpeg 支持；
- 输出目录是否可写；
- 磁盘余量是否大于估算输出和临时空间的 1.25 倍。

运行时错误按任务隔离。用户可见错误必须包含中文摘要、失败阶段、素材或运行时名称、日志路径和建议操作。不得向用户显示未经处理的堆栈作为唯一错误信息。单个任务失败不停止队列；应用级致命错误记录崩溃报告，但不包含媒体内容或用户字幕正文。

## 12. 开发标准

- 启用 nullable reference types、隐式全局 using 和 .NET 分析器；项目代码警告视为错误。
- 公共边界使用不可变 record 或只读接口；禁止跨层传递松散字典和未约束 `object`。
- 所有长操作必须接受 `CancellationToken`；不得在 UI 线程调用阻塞 I/O 或 `.Result`/`.Wait()`。
- 外部进程使用 `ProcessStartInfo.ArgumentList`，不得拼接 shell 命令。
- 文件路径始终使用绝对路径和标准化比较；项目文件不保存模型、密码或 API 密钥。
- 日志只记录排障所需的阶段、运行时版本、退出码和相关文件路径；字幕正文与识别文本默认不写入诊断日志。
- View code-behind 仅用于无法自然绑定的窗口行为；业务逻辑必须位于 ViewModel、Application 或 Domain。
- 新行为采用测试先行的红—绿—重构循环；错误修复必须先有可复现测试。
- 提交使用 Conventional Commits；每个提交保持可构建、可测试、职责单一。
- 不保留占位按钮、空命令、TODO 或“稍后实现”界面。
