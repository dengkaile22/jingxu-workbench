# 与 .NET 版的功能对照审计（按验收标准逐条核查）

**为什么要写这份文档**

此前几轮我按「用户报什么修什么」推进，导致同一类问题被逐个发现而不是一次查清：
logo 文件一直在仓库里却没人用、随机贴纸库开关能勾选但不生效、Tesseract 是
1 字节占位文件、OCR 因命令写法错误从未成功过。这些都是**同一类**问题——
「代码里声明了，但实际不生效」。

## 一、本轮查出的问题与处理

| # | 问题 | 性质 | 证据 | 处理 |
|---|------|------|------|------|
| 1 | logo 与图标文件存在但从未使用 | 遗漏 | Python 包内无任何图片；标题栏用色块「炳」字代替；exe 显示 PyInstaller 默认图标 | 已接入标题栏/关于/窗口图标/exe 图标，快捷方式自动跟随（WiX 取 exe 图标） |
| 2 | 随包等宽字体未使用 | 遗漏 | .NET 有 `Assets/Fonts/IBMPlexMono-Regular.ttf`（用于数字与时间码），Python 直接用系统 Consolas，缺失时退化为比例字体、时间码错位 | 复用同一份字体（SIL OFL 1.1），启动时注册；实测字宽 7/7/7 等宽成立 |

| 4 | 设置页后台线程向已释放信号源发信号 | 崩溃风险 | 关闭窗口后必现 `RuntimeError: Signal source has been deleted`（由布局测试暴露） | 加 `shutdown()` 标记 + 异常兜底，`closeEvent` 中调用 |
| 5 | 字幕 OCR 从未成功 | 功能性缺陷 | 两处缺陷详见下节 | 已修复，并以真实素材验证 |
| 6 | 高 DPI / 窄窗口截断 | 合规项 | 规格 13.3 明确要求 | 已加自动化检查（见下节），当前通过 |

## 二、OCR 的两处真实缺陷（第 5 项展开）

**缺陷 A：TSV 被当作配置文件。** 命令写作
`tesseract frames.txt stdout -l chi_sim+eng tsv`，而 tesseract 把 `outputbase`
之后的**首个位置参数当作配置文件**，于是报 `read_params_file: Can not open tsv`
并静默退回纯文本输出；`parse_tesseract_tsv` 解析不到任何词 → 0 个区域。
修复：改用 `-c tessedit_create_tsv=1`。

**缺陷 B：检测框被重复映射。** Tesseract 处理整帧，坐标已是全画面绝对比例，
检测链路又按扫描区（y 从 0.55 起）映射一次，把框压扁下移：

| | y | 高 |
|---|---|---|
| 文字真实位置 | 90.5% | 3.3% |
| 修复前 | 95.7% ❌ | 1.5% ❌ |
| 修复后 | 89.9% ✅ | 4.5% ✅ |

**顺带改进**：检测框留边（水平 ±1%、垂直 ±0.6%，单行撑到最小高度 3.5%），
否则去字幕在字缘留残影。

**实测**：真实 1080×1920 素材 + 烧录硬字幕「这是硬字幕测试」，
识别正确、置信度 0.95；去字幕实测 blur 糊成不可读、delogo 完全清除。

## 五、流程改进

1. **以验收标准为检查表**，而不是等用户逐个报问题（本文件即该做法的产物）。
2. **「声明即生效」原则**：任何界面开关、字段、资源都必须有对应的消费点与
   自动化断言；不得存在「能点但不变」的控件（规格第 12 节要求）。
3. **真实素材验证优先于合成桩**：OCR 的两个缺陷用合成 TSV 桩测不出来，
   只有真实视频 + 真实 Tesseract 才暴露。后续涉及外部工具的功能一律加真实冒烟。
